# Implementation Plan

## Strategy decision

| Strategy | Verdict | Why |
|---|---|---|
| **A. Repair an existing web build** | ❌ Not possible | There is no client of any kind in the repository, web or otherwise. |
| **B. Unreal Pixel Streaming** | ❌ Not applicable | The project is not Unreal Engine. Even for the real (Unity) BitCraft client, streaming would need the closed-source client, licensed data, and GPU hosting. |
| **C. Separate web client** | ✅ **Implemented** | The only route to something playable in a browser. Built on the **same backend technology as the repository (SpacetimeDB 2.10, Rust modules, server-authoritative reducers + scheduled agents, external login service)** so it extends the existing architecture rather than replacing it. |

**What C is, honestly:** *KayKit Arena* is a new, small top-down action-RPG prototype with original rules and CC0 KayKit art. It is **not** BitCraft, does not use BitCraft data or branding, and does not connect to the BitCraft modules (they cannot run gameplay without their proprietary static data; see PROJECT_AUDIT.md B2/B3).

## Why not plug the browser into the BitCraft modules directly?

The SpacetimeDB TypeScript SDK *can* talk to the BitCraft modules (same protocol), and they were built and published locally to prove it. But every gameplay reducer requires static data that is not public, player creation goes through the global module and an absent login server, and BitCraft's NOTICE forbids reusing its world data and branding in other experiences. Building a fake data set big enough for 125 tables would be a game-design project of its own and would still misrepresent the original game.

## Delivered components (all under `web/`)

| Component | Tech | Responsibility |
|---|---|---|
| `arena-module/` | Rust, SpacetimeDB 2.10 | Authoritative world: players, enemies, pickups, combat events. 20 Hz scheduled `world_tick` agent (movement integration, collision, enemy AI, respawns). Reducers validate every intent (input vector, attack cooldown/range/arc, potions). Only a registered gateway can authorize sessions. |
| `gateway/` | Node 22, zero runtime deps (`node:http`, `node:crypto`, `node:sqlite`) | REST API (`/api/health`, `/api/config`, `/api/auth/register`, `/api/auth/login`, `/api/leaderboard`), scrypt password store, verification of SpacetimeDB identity JWTs (ES256), allow-listed proxy to SpacetimeDB (WebSocket subscribe + identity endpoints only), static hosting with gzip cache and security headers, graceful shutdown, JSON logs. |
| `client/` | TypeScript, Vite 7, three.js r186, SpacetimeDB TS SDK 2.10 | Login/registration, class select (portraits rendered from the models), HUD, inventory placeholder, leaderboard, menu, desktop and touch controls, client-side prediction with server reconciliation, interpolation, animations, minimap. |
| `shared/map.json` | generated by `shared/generate-map.mjs` | Single source of truth for layout, colliders and spawns; embedded into the module (`include_str!`) and imported by the client. |
| `tools/build-assets.mjs` | gltf-transform | Reproducible download of pinned KayKit commits + optimisation (≈30 MB → 6 MB). |
| `scripts/` | bash | `dev.sh` (one command for everything), `start.sh` (production-style), `register-gateway.sh`. |
| `tests/e2e.mjs` | Playwright + Chromium | Full-stack browser test (desktop + mobile/touch, two players, reconnection, re-login, shutdown). |

## Next steps (not done)

1. Run the E2E suite and a manual play session on real GPUs / phones; tune performance (merge character sub-meshes into one skinned mesh per character to cut ~200 draw calls).
2. Deploy: TLS reverse proxy (Caddy/nginx) → gateway; SpacetimeDB on the same private host; back up `web/.data/` and the SpacetimeDB data dir; rotate the gateway token if leaked (delete the file, restart, re-register).
3. Gameplay depth: real pathfinding for enemies (they currently only steer around single obstacles), more enemy types, loot/equipment (inventory is a placeholder), PvP toggle, more maps.
4. If Clockwork Labs later publishes client tooling or sample data, revisit a real BitCraft web client.
